# نظام الدردشة بدون إنترنت (Offline Chat System)

يعد نظام الدردشة بدون اتصال بالإنترنت في تطبيق **Link Note** ميزة حيوية تتيح للمستخدمين التواصل ومشاركة الملفات (الصور والتسجيلات الصوتية) عبر مسافات قريبة دون الحاجة إلى خادم مركزي أو اتصال بالإنترنت. يعتمد هذا النظام على تقنية **Google Nearby Connections**.

---

## 1. المكونات الأساسية للنظام

يتكون النظام من عدة طبقات تعمل معاً لضمان تجربة مستخدم سلسة:

### أ. طبقة الاتصال والتبادل (Connectivity & Discovery)
*   **NearbyConnectionManager:** هو عصب النظام. يدير عمليات الإعلان (Advertising) والاكتشاف (Discovery).
*   **NearbyEndpointManager:** مسؤول عن تتبع الأجهزة المكتشفة، وإدارة حالتها (متصلة/غير متصلة)، وربط معرف الجهاز التقني (Endpoint ID) بمعرف المستخدم الدائم (UUID).

### ب. طبقة الهوية (Identity Management)
*   **NearbyIdentityModel:** يمثل هوية المستخدم (الاسم، المعرف، وصورة البروفايل).
*   **NearbyIdentityManager:** يدير هوية المستخدم المحلي ويقوم بتحويلها إلى صيغة JSON ليتم تبادلها مع الآخرين.

### ج. طبقة البروتوكول (Protocol Layer)
*   **Protocol & Packet:** بما أن البيانات تُرسل كبايتات خام، فإن هذا الجزء مسؤول عن تغليف الرسائل في "حزم" (Packets) تصف نوع المحتوى (نص، صورة، صوت) وبيانات المرسل.

---

## 2. آلية العمل (Workflows)

### المصافحة (Handshake)
عند إنشاء اتصال بين جهازين، يقوم النظام بعملية "مصافحة" تلقائية:
1.  يرسل كل جهاز بيانات هويته الكاملة (بما في ذلك صورة البروفايل) بصيغة JSON.
2.  يستقبل الطرف الآخر هذه البيانات ويحدث قائمة الأجهزة المكتشفة لديه ليعرض الاسم والصورة الصحيحين.

### تبادل الرسائل النصية
1.  يتم تغليف النص في حزمة `MessageType.text`.
2.  تُحول الحزمة إلى بايتات وتُرسل مباشرة.
3.  يستقبل الطرف الآخر البايتات، يفك تغليفها، ويعرضها في واجهة الدردشة.

### تبادل الوسائط (الصور والتسجيلات الصوتية)
بسبب حجم الملفات، يتم إرسالها عبر مسارين:
1.  **المسار الأول (البيانات الوصفية):** يتم إرسال حزمة صغيرة تخبر المتلقي بأن هناك ملفاً قادماً، وتزوده بمعرف الملف ووقت الإرسال.
2.  **المسار الثاني (الملف الفعلي):** يتم نقل الملف باستخدام خاصية `sendFilePayload` التي توفرها مكتبة Nearby.
3.  **التجميع:** يقوم المستقبِل باستخدام `VoiceTransferHandler` أو `ImageTransferHandler` لربط الملف بالبيانات الوصفية بمجرد وصولهما معاً.

---

## 3. التعامل مع التحديات التقنية

*   **حالة التسابق (Race Conditions):** تم معالجة مشكلة وصول الملف قبل بياناته الوصفية (أو العكس) من خلال منطق انتظار ذكي يضمن عدم ضياع أي رسالة.
*   **استقرار الاتصال:** يقوم `ChatSessionManager` بإدارة الجلسات لضمان استمرارية المحادثة حتى في حال انقطاع الاتصال المؤقت وإعادة الربط.
*   **كفاءة الذاكرة:** يتم تدوير مشغلات الصوت واستخدام التخزين المحلي للملفات لتقليل استهلاك الذاكرة.

## 4. المسارات البرمجية الهامة

| المجلد/الملف | الوظيفة |
| :--- | :--- |
| `lib/features/offline_chat/data/services/` | المحركات الأساسية للاتصال والPayloads. |
| `lib/features/offline_chat/data/handlers/` | معالجة الرسائل الواردة، الصادرة، والتسجيلات. |
| `lib/features/offline_chat/data/models/` | تعريف هياكل البيانات والقواعد البرمجية (Protocol). |
| `lib/features/offline_chat/presentation/` | المتحكمات (Controllers) والواجهات الرسومية. |
